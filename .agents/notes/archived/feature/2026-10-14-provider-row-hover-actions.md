# Agent Note: 供应商行按悬浮与焦点显示操作

Status: implemented
Archived: 2026-10-16

## Problem

供应商切换列表的每条档案常驻显示启用、重新登录、编辑、测试、用量、删除和刷新按钮，重复动作抢占名称、模型和状态的阅读注意力。用户要求仅在悬浮当前行时显示按钮。

## Decision

由 `base/provider-list.css` 统一控制 Codex 与 Claude 的供应商行操作可见性。空闲行隐藏动作轨、排序手柄及摘要刷新按钮；悬浮当前行、行内键盘焦点或拖动时显示。触摸设备通过点按行产生的悬浮态显形，点按后悬浮保持到点按别处。不使用任何指针能力媒体查询或设备分支，显隐是无条件的一条交互规则。显隐以 `--asb-motion-node` 时长的透明度过渡呈现，与行内披露面板同一动效节奏；减少动态效果偏好把时长归零，自动退化为瞬时切换。显隐默认过渡以零特异度的 `:where(.asb-row-action)` 声明，排序手柄在自有过渡清单中补充 `opacity`，其按压反馈不被同权重的通用声明替换。只使用透明度和指针命中控制，保留布局占位与原有 Tab 顺序，不引入 React 状态或第二套按钮。名称、模型、地址、已应用、用量与错误始终显示，详情面板内的操作不受影响。

`ProviderRowShell` 的排序手柄与动作轨、`UsageSummaryView` 的刷新按钮显式声明统一的 `.asb-row-action` 标记；`provider-list.css` 只通过这个标记控制显隐，不再分别匹配三个控件的位置或依赖 `.asb-usage-freshness > button` 的内部 DOM 结构。行悬浮、焦点和拖动直接使用浏览器伪类与已有拖动状态，不增加监听器、设备状态、开关、兼容选择器或回退路径。

既有[三轨布局](../architecture/2026-10-13-provider-row-three-rails.md)继续拥有布局；本决定只调整操作可见性。[扩展操作显性化](../bug-fix/2026-09-24-extension-visibility-and-focus.md)针对扩展批量作用范围，与本次供应商行无关。

## Alternatives considered

- 常驻全部按钮：无需发现交互即可操作，但重复按钮正是用户希望减少的视觉密度。
- 隐藏后移除布局占位与键盘焦点：可以回收操作区域宽度，但悬浮时会移动模型和地址，键盘用户也无法进入按钮，因此不采用。
- 以指针能力媒体查询分流（`(hover: hover) and (pointer: fine)`，含曾用的 `not (any-pointer: coarse)` 排除）：最强的理由是让触摸设备默认常显、鼠标设备悬浮收起，各得其所；但这是环境检测而不是交互本身，真实机器上只要带有触摸屏整条规则即告失效，每新增一种输入形态还要再加分支。统一为无条件的悬浮/焦点规则后，触摸由点按悬浮承担，不再需要任何能力探测，媒体查询整体删除。

## Verification

静态检查覆盖共享 `ProviderRowShell` 的 Codex 第三方、官方与 Claude 消费者，以及共用摘要刷新按钮的显式标记；唯一显隐规则无条件作用于空闲行，保留焦点顺序与布局占位。旧的动作轨、排序手柄和摘要内部结构显隐选择器已删除；组件检查确认没有新增状态、事件、依赖或重复操作。最终差异与笔记结构校验随改动执行；遵循项目限制，不运行编译、类型检查或自动化测试。真实桌面悬浮、Tab 与触摸效果未运行验收。

## Consequences

重复按钮只在当前交互行出现，数据与错误信息始终可读。代价是鼠标用户需要悬浮才能发现操作。按钮仍保留占位，因此此次只减少视觉噪声，不收紧行高；触摸设备首次点按行即显形并保持，代价是触摸用户需要先点一次行，没有默认可见的操作提示。

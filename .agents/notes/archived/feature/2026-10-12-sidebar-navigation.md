# Agent Note: 全局导航迁移至左侧纯图标轨

Status: implemented
Archived: 2026-10-13

## Problem

全局导航原先横排在顶栏（`AppShell` 的 `.asb-topbar`）：品牌区居左、六个页面按钮居中、窗口动作居右，顶栏同时承担拖拽区。对照 Codex 桌面版与 cc-switch 两个同类桌面工具，共同形态都是「导航在左侧、内容在右侧」；本项目页面全部可语义化为单个图标，顶栏横排文字导航是网页残留形态。

## Decision

应用外壳改为左右两栏：`AppShell` 拥有骨架（`asb-shell` = 图标轨 + `asb-body` 工作区列），新组件 `SideNav`（`src/app/SideNav.tsx`）拥有左轨。事实分布：

- **固定 64px 纯图标轨**（Codex 桌面左轨同型），无收起态、无宽度过渡、无文字：顶条放应用标记（兼 Tauri 拖拽区），软件名「Agent Switchboard」由右侧相邻标题条显示，与标记垂直居中并可拖拽；五个工作区图标纵列可滚动，细分隔线下贴底「设置」图标。
- **图标语义与来源**：共享 `src/components/icons.tsx` 统一拥有库图标绑定，`SideNav` 只拥有页面到语义图标的映射，导航统一使用 24px 尺寸。供应商切换为双向箭头、客户端配置为水平滑杆、扩展为拼图、会话记录为对话框、用量监控为递增柱图、设置为齿轮。导航图标的 Phosphor 来源与当前页 `regular` / `fill` 形态由[侧栏图标状态](2026-10-12-sidebar-icon-states.md)拥有，其他图标保持既有 Lucide 绑定。侧栏无自绘组件、独立路径数据或图标偏移修正。SVG 块级化消除基线缝隙。
- **对齐与材质**：`tokens.css` 拥有侧栏宽度与外框底色，`base/shell.css` 唯一拥有外框、工作区面板与导航样式。条目固定为 40px 方形、间距 4px，列表项居中；工作区列表通过 `scrollbar-gutter: stable both-edges` 对称预留滚动条空间，与应用标记和底部设置保持同一轴，焦点轮廓内收避免裁切。顶部按钮栏与左轨共用外框底色，浅色为 `#eceef1`、深色为 `#111e2b`；主工作区位于 64px 标题栏下方，以既有 12px 圆角、1px 细边框和右侧/底部 4px 间隙嵌入外框。移除侧栏贯穿分隔线与全窗口环境光 DOM 层，环境光随工作区底色绘制并由 `overflow: clip` 裁切，不增加滚动容器；页面继续拥有内容滚动。悬停与选中由主文字色混入外框底色生成；当前图标使用主文字色，其他控件仍消费原有 rail 材质。偏好预览图同步两套外框颜色与嵌入式工作区轮廓。
- **名称与提示**：页名不落轨面，由条目按钮的 `aria-label` 承载可访问名称；共享 `Tooltip`（Radix）直接绑定可转发 ref 的 `Button`，悬停与键盘聚焦时在右侧浮现，激活即收。移除导航按钮外的 shrink-to-fit 提示容器，避免按钮宽度受 SVG 内容影响；工具条按钮（置顶/更新）的提示接线保持原状。
- **无持久化**：图标轨是唯一形态，不引入任何收起状态或设置字段——应用偏好契约保持 `language` 世代形状不变。
- 页面内部的分类页签（`WorkspaceHeader` primary 行、设置页顶部页签）一律不动：全局导航与页内导航是两级结构。

标题栏左侧的全局反馈由[标题栏统一全局信息](2026-10-12-titlebar-information.md)拥有；本篇继续拥有侧栏与窗口动作的外壳结构。

### 契约迁移

中途构建（未发布但本地安装包已产出）曾携带 `sidebarCollapsed` 设置字段，磁盘上可能存在该形状的设置文件。当前契约删除该字段后，启动升级链插入 `SidebarEraSettings` 一环：严格完整解析该形状（`deny_unknown_fields`）→ 丢弃收起状态 → 原子重写为当前契约；v0.2 链尾（无 `language`，钉住中文）保持不变。无兼容分支、无双读：运行时读取始终严格拒绝带 `sidebarCollapsed` 的文件，只有启动升级这一条显式路径能迁移它。

## Alternatives considered

- **可收起的文字侧栏（260px 图标+文字 ↔ 64px 图标轨）**：信息密度最高、新用户无需学习图标语义；但本项目仅六个顶级页且全部可语义化，双形态引入收起状态、持久化与过渡动画三类机制，收益不抵复杂度——用户明确裁决纯图标。否（文字侧栏 + localStorage 收起状态 + 盖板动画的中间迭代均止于此）。
- **收起开关放标题条左端（Codex 式）**：位置固定、肌肉记忆稳定，曾因 44px 开关在品牌行放不下而采用；图标轨定型后开关随收起语义一并删除。否。
- **cc-switch 的盖板方案（宽度一步到位 + 盖板 transform 动画）**：避免逐帧布局重排；需要独立盖板图层与 JS 编排，随收起形态一并消失。否。
- **保留 `sidebarCollapsed` 字段以兼容中间构建**：最强理由是已安装的本地包会写出该字段；但严格升级链一环即可确定性迁移（丢弃字段重写），保留死字段违反「无兼容分支」约束。否。
- **维护侧栏专用自绘图标**：能够逐个控制轮廓和光学偏移；但需要独立维护一套图形规范，用户明确选择开源库，因此统一复用共享库图标绑定。

## Consequences

- 收益：内容列拿到全部横向空间且永久稳定（无宽度变化引起的工作区重排）；导航语义零学习成本（悬浮提示 + 可访问名称双通道）；动效、持久化、双态几何三类机制整体消失，`SideNav` 无状态。
- 代价：图标语义需要一次学习，悬浮提示是唯一回收通道（触屏场景无 hover，但本项目是桌面鼠标/键盘工具）；升级链现有两个历史形状（v0.2、sidebar 世代），字段稳定后应评估改按版本号迁移。Beta 渠道标注移除，渠道事实由「关于」页唯一承载。
- 外观验证使用实际侧栏样式与 SVG 的隔离静态预览，覆盖深浅主题、280px 短窗口滚动与 125% 缩放；六个按钮在默认比例下均为 40px 方形且中心位于轨道 32px 处，125% 时同比缩放为 50px 方形、中心位于 40px 处。静态预览不覆盖真实 Tauri 窗口、Radix 提示运行时或设置升级链；这些仍需在获准启动应用后验证。
- 笔记结构由仓库现有的树、格式、归档三个脚本校验；本机缺少 `tsx` 时可用 Node 24 直接执行原脚本。前端构建、类型检查与项目自动测试遵循仓库的显式授权规则。

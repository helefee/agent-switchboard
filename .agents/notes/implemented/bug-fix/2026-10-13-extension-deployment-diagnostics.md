# Agent Note: 扩展部署批次与 MCP 检测的事实归属

Status: implemented

## Problem

部署批次按扩展定义拒绝重复操作，使同一扩展的多目标启停和完整移除无法执行。固定版本的 Skill 在跳过部署后仍被记录为已应用最新修订，解除固定时错误显示同步。MCP 检测借用待安装目标、忽略目标工作目录，并使用非标准发现请求和重复协议分支；流式响应、任务取消及结果刷新也存在断裂。

## Decision

部署计划先合并同一扩展的同类操作，再通过一个文档工作区生成原子批次；重叠绑定、重复目标和相互冲突的操作直接拒绝。每个实际渲染内容的计划生产者拥有完整的部署后绑定及其 `lastAppliedRevision`。可见性变更、修复、历史恢复及固定旧内容保留对应版本，应用阶段不再按操作名称猜测部署版本。显式跳过的目标只进入操作报告，不执行步骤，也不提交绑定或基线。Skill 同步状态比较目标内容、部署基线和当前或固定摘要，不能由版本号代替内容事实。

安装和 MCP 检测复用受支持目标的枚举，检测有独立选择器，包含已安装目标。后端验证定义修订、客户端、项目及工作目录；应用目标使用用户主目录，项目目标使用注册根目录，Codex stdio 再应用其专属 cwd 与启动超时。Claude Windows 启动器包装只作用于 Claude 目标。

stdio 和 Streamable HTTP 共用标准 `initialize`、`notifications/initialized` 和已声明能力的分页目录检查。版本协商接受明确支持的标准版本，不存在发现后回退分支。HTTP 按请求 id 增量消费 SSE，支持分块、多行事件、通知和服务端请求，收到匹配响应即结束；会话、协议头和请求取消由同一个连接拥有。读写、分页及输出大小均受界限约束。

后端任务表拥有检测状态、统一截止时间、取消与有限保留的终态。前端保留任务标识并轮询至终态，关闭管理弹窗请求取消，完成后刷新扩展工作区。结果保存仅接受仍存在的当前定义修订，每个目标保留最近一次结果；列表和弹窗都读取这份保存结果。IPC 读模型以 `checks` 取代单个 `lastCheck`，所有直接消费者同步切换，不保留旧字段别名。持久化检测结果格式不变。

Skills 与 MCP 共用表格的操作表头、单元格和按钮组左对齐。部署与诊断中的绑定、安装目标、能力审计、依赖、凭据映射、检测结果、文件变更及历史执行结果统一接入共享 `Table`。目标、状态、版本和操作分别成列；表头和内容沿用全局左对齐契约。窄窗口由模块内的横向滚动区域承接表格，长文本在列内换行。基本资料沿用全局事实行，操作控件继续请求已有回调，表格不产生第二份业务状态。模拟阶段进度、前端独立超时、重复检测状态容器及非标准协议分支全部移除。

## Alternatives considered

- 前端逐绑定循环执行可以绕过重复定义限制，改动较少；但拆散原子批次，留下部分部署状态，因此合并请求后沿用单一计划及执行器。
- 在应用阶段按操作名决定是否推进版本能集中修改点；但同一个停用操作可能只改可见性，也可能重写当前 MCP 配置，因此由实际准备内容的生产者记录覆盖版本。
- 延长前端计时器可以减少过早超时；但仍有第二个截止时间且关闭弹窗后可能遗留检测，因此后端拥有任务终态与取消。
- 保留探测后回退的协议分支能容忍更多非标准服务；但增加重复状态并掩盖协议错误，因此只保留标准初始化和明确的版本协商。
- 保留安装卡片和内联文字列表能少占列宽，适合单条阅读；但目标、状态和操作缺少固定列，难以比较多目标部署，因此重复结构化记录使用共享表格，并在窄窗口保留横向滚动。

## Consequences

同一扩展的多个非重叠绑定在一个计划中启停或移除，共享文档只写一次。固定 Skill 跳过更新不推进应用修订，解除固定后由内容摘要准确显示待部署。检测结果不再被未安装目标、未结束的流或旧定义修订误导。

检测仍需要用户明确点击，可执行其定义的命令或访问端点，凭据值不进入错误文本或结果记录。SSE、WebSocket 与需要交互授权的端点明确标为原生客户端确认，不伪装成通过。检测只读取握手与目录，不调用工具。终态消费或保留期到期后任务标识失效，持久化目标结果仍可重新查看。

# Agent Note: 当前连接事实与配置写入差异分离

Status: implemented

## Problem

供应商概览将档案完整重投影是否零差异、整文件是否等于历史写入、备份来源混成一个匹配状态。原生官方配置有模型而官方档案模型为空、实时参数存在而保存意图为自动时，即使用户未操作也不能通过该比较；未关联档案、偏好差异和投影失败因此共用一条警告。恢复备份和读取尚未完成也使用警告色，实际设置校验错误与待恢复事务反而没有进入连接卡。

## Decision

删除运行时匹配状态及 Rust/TypeScript 契约、产出逻辑、专用网关重投影方法、三个展示消费者和词典，不新增替代状态或兼容分支。该状态从不落盘，不需要数据迁移。当前身份继续由连接、账号绑定与 `activeProfileId` 唯一确定，当前模型和偏好来自实际文件；模型、偏好、注释和上次写入均不参与配置健康推断。

具体差异只由既有切换预览和诊断产生，预览错误保留原有结构化原因。整文件哈希继续保护预览、执行、恢复及撤回的快照，不用于推断用户是否修改配置。写入历史继续显示为历史事实；同一连接的档案有歧义时，历史仅在现有候选中消歧，不凭历史认领另一连接。

连接卡将未读取和未关联档案作为中性信息。读取、语法、客户端设置校验、事务恢复、作用域和写入锁问题继续展示具体原因；诊断里的网关观察与写入授权不依赖被删除的状态。自动设置仍表示显式应用时移除对应字段，官方模型为空时的候选删除仍由预览呈现，不通过回填档案或自动覆盖配置消除差异。

原有「移除外部修改状态」决定被本决定完整吸收：删除外部修改推断，保留独立的过期预览和保存保护；原来的「只隐藏 UI、保留后端分类」理由与拒绝理由继续成立。旧笔记归档。[连接卡档案查找](../feature/2026-09-22-route-card-website-link.md)只部分相关，保留其名称与官网的 `app + activeProfileId` 所有权。

## Alternatives considered

- 只改警告颜色或文案：改动最少，能缓解用户误解；但全量重投影与历史哈希仍参与日常状态，还会将预览错误压成未匹配，拒绝。
- 新建更细的匹配枚举：能区分未关联、参数差异和恢复来源；但身份、具体差异、写入历史已有各自所有者，增加第二份派生状态及穷举维护面，拒绝。
- 自动把当前配置回填进档案或重新应用：可以使重投影达到零差异；但会改变用户保存意图或实际配置，状态读取不应拥有该副作用，拒绝。
- 删除整个连接卡提示区：能一次移除所有误警示；但会丢失读取错误、配置语法、事务和锁等有事实依据的问题，拒绝。

## Consequences

日常状态没有匹配分类的第二个事实来源，正常的原生配置、偏好差异、注释变化和恢复来源不会产生匹配警告。代价是保存意图与实际文件的完整差异需要在预览或诊断查看具体字段。身份识别仍不证明登录、网络或模型可用；若未来需要常驻差异，应先明确独立的用户动作与字段范围，再复用预览所有者，不恢复历史哈希推断。

真实读取、语法、设置校验、恢复、作用域、锁及网关问题保留各自诊断；卡片补充设置错误与恢复原因，客户端配置页不再将读取失败误称语法错误。切换执行器、备份和撤回的哈希防护不变。

## Verification

状态模块新增六个内存回归用例，覆盖 Codex/Claude 原生官方接入、模型和偏好不同、注释、未关联档案、历史写入与恢复、设置错误以及公共序列化契约；前端身份查找新增三个用例；供应商诊断新增两个用例，覆盖预览失败原始原因及读取、语法、设置、恢复错误。既有网关故障和过期预览拒绝用例保留。用例不读写真实用户配置或认证文件。

验证范围是旧引用检索、差异与笔记结构检查、源码和组件静态审查。按项目规则不运行编译、类型检查、自动化测试及桌面验收；新用例尚未执行，不将源码审查当作这些验证通过。

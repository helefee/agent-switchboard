# Agent Note: 品牌图标由同一矢量母版生成

Status: implemented

## Problem

用户要求重新设计软件 logo，并明确保留蓝、紫、橙、粉渐变。应用、托盘、关于页和 README 已引用 src/assets/app-icon.svg，但官网 favicon 需要手工复制，Windows 安装器又手写了一套旧交叉路径。只替换母版会留下不同品牌标记；以后每次修改仍须同步多份几何。

## Decision

src/assets/app-icon.svg 继续作为唯一母版，使用两条旋转对称的折返路径形成 S，中部斜向留白表达切换，透明背景上共享蓝紫粉橙线性渐变，不引入滤镜、字体或第三方图形。

scripts/sync-app-icons.mjs 在既有原生图标生成成功后，同时复制原生 SVG 与官网 favicon。Windows 安装器将生成的 128x128@2x.png 作为嵌入资源，由现有 WPF Image 与 PNG 解码器显示，删除 SwitchPath 和只供旧标记使用的 BrandBlue/Violet 画刷。执行文件图标仍使用同批生成的 ICO，不复制矢量几何。

中英文 README 与官网共用的八张界面截图从当前前端重新截取，消除图片内嵌的旧标记；docs/screenshots 与 website/public/media/screenshots 同批逐字节同步，截图日期与官网替代文本随图片更新。截图只消费隔离模拟响应并阻断外部请求；演示模型名称沿用已注明来源的既有值，不声称重新核对官方模型目录。

检索活跃笔记的 sync-app-icons、app-icon.svg、母版、图标生成和 InstallerWindowLayout 没有找到同主题所有者；侧栏图标状态与标题栏信息笔记只拥有导航/通知语义，属于无关决定。DESIGN.md 继续拥有视觉事实。

## Alternatives considered

- 安装器继续手绘矢量：任意 DPI 下保持矢量清晰，也无需嵌入 PNG；但需要在 WPF 中重复路径与渐变，重新引入第二个几何来源。现有 20px 标记由 256px 源图缩小即可覆盖常见缩放。
- 只改 SVG，再手动复制官网 favicon：改动最小；但安装器继续保留旧标记，且后续生成仍可能漏同步官网，不能满足统一品牌资源的当前需求。

## Verification

- npm run icons:sync 成功生成原生 PNG、ICO 和 ICNS；母版、原生 SVG 和官网 favicon 的 SHA-256 相同。
- 安装器项目与主题 XML 能解析，嵌入资源名称和加载名称一致；源码检索没有残留 SwitchPath、旧路径或专用 BrandBlue/Violet 画刷。
- 同源静态预览人工检查浅深背景及 16、20、24、32、64px 显示，斜向间隙保持可辨；同时检查 24px 标记与软件名的组合。预览不是桌面或安装器运行验收。
- 2026-10-14 从本地 0.3.3 生产前端产物重新截取八张演示截图，每张核对新标记，两处副本逐字节一致且尺寸符合既有声明，最终截取没有页面渲染错误。独立沙箱目录与空白临时浏览器上下文只消费模拟响应，不操作桌面窗口。生产图标是独立 SVG 资源，核对实际资源内容与母版，不依赖开发态内嵌 data URI。
- 用户授权的 0.3.3 本地构建完成前端类型检查、生产构建、Rust release 编译、NSIS 打包与 WPF 安装器编译。首轮仅在 NSIS 工具下载遇到 DNS 错误，复用编译结果重试打包通过；重复写入包类型的提示经二进制标记核对确认为已写入 NSIS 类型。
- 对安装包只做静态解包与资源核对：新标记、背景、安装引擎的嵌入字节与源文件匹配，NSIS 中的主程序与本次编译文件匹配，版本为 0.3.3 / 0.3.3.0。构建输入快照未变化；笔记结构与差异检查通过，未执行安装程序或自动化回归测试。

## Consequences

应用、官网、原生图标与安装器共用母版，删除安装器的第二套几何与旧专用画刷；新增的唯一打包输入是已有生成流程输出的 PNG。WPF 标记由矢量改为高分辨率位图，极端放大超出 256px 源图时存在采样上限。本地 0.3.3 安装包和当前文档截图均已刷新，历史发布记录与真实用户环境不改写；安装后的系统图标、安装器运行显示与真实配置行为尚未验收。

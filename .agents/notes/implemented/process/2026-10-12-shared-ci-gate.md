# Agent Note: 开发机与远程流水线共用源码门禁

Status: implemented

## Problem

GitHub 直接打包而 CNB 只跑 Rust 测试与前端构建，本地验证没有统一入口。笔记检查还通过未锁定的 npx tsx 临时联网，测试夹具的契约漂移直到发版后才暴露。

## Decision

由 scripts/ci.mjs 顺序执行笔记门禁、Node 测试、锁定依赖的 Rust 工作区测试及前端构建，遇错即停。npm run ci 是开发机、GitHub 四个平台和 CNB 的共同入口；各平台继续拥有自己的系统依赖与原生打包步骤。.node-version 唯一拥有 Node 版本，笔记工具使用原生 TypeScript 执行，移除 npx tsx 路径。测试使用隔离配置目录，失败日志保留在忽略的 .tmp 内。

Windows MSIX 打包接受 SDK 标准变量 WindowsSdkVerBinPath；设置该变量时只使用其指向的 SDK，不存在则明确失败。未设置时使用既有系统 SDK 安装位置。开发机可用微软独立 SDK 构建工具，不要求改变系统安装。

与[笔记机制](2026-09-22-agent-notes.md)部分重叠，保留其结构决策并同步执行方式；[构建缓存保留](2026-09-24-local-build-cache-retention.md)拥有缓存策略，本方案不改变它。检索没有发现其他共用 CI 门禁方案。

## Alternatives considered

- 各流水线分别维护检查命令：平台调整直接方便，但容易再次遗漏测试，不能证明本地通过的检查就是远程执行的检查。
- 本地模拟 macOS 与 Linux 全部打包：覆盖面最完整，但 Windows 开发机不能替代 macOS 原生工具链；共用源码门禁和 Windows 打包在本地验证，其余原生包由远程矩阵验证。

## Verification

Node 22.23.2 下按锁文件重新安装依赖，共用入口通过：18 篇笔记、11 项前端测试、529 项 Rust 测试及前端类型检查/生产构建。唯一忽略项是由其他测试调用的子进程辅助入口。七处测试编译错误修正为当前接口，删除已废弃清空缓存行为的测试；五处夹具修正为合法排序位置及明确创建的临时目录，不放宽产品校验。首轮受网络沙箱限制的本机 HTTP 测试失败另存日志，开放本机模拟服务访问后全量复跑通过。

Windows 独立 SDK 的 MSIX 构建及解包契约验证通过，安装器与 MSIX 的远程同脚本凭据扫描通过。安装器复用本轮已构建并核对载荷的 0.3.2 成品，SHA-256 为 EE90686EDD0A9D5DD6979A887AC4E83A63E5691C24BEAEEE9206061799EB4998；后续源代码修改均为测试及 CI 工具，不改变该应用载荷。源码门禁通过与平台原生打包分别记录，不把 Windows 结果扩大为其他平台通过。

## Consequences

全平台测试增加远程耗时；本地 Windows 通过不能宣称 macOS/Linux 原生打包通过。外部在线 Codex 验证保持显式选择，不读取真实客户端配置。

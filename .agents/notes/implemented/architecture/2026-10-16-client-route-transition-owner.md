# Agent Note: 客户端页签切换由单一可取消动画控制器拥有

Status: implemented

## Problem

供应商页分别保存方向和退场客户端，客户端配置页另存 from/to；两套状态都依赖动画事件和 400ms 计时兜底。供应商超时只清退场端，方向可能残留并在后续列表挂载时重播。快速反向点击会重启 CSS 动画，从初始位置跳变。共享关键帧不足以统一生命周期。

## Decision

两个工作区直接使用 useClientRouteTransition，选择客户端仍调用既有 providers.selectApp，控制器只拥有一次点选产生的 from/to 记录与实际 Web Animations 对象。正文通过控制器的稳定类型化 callback ref 直接登记；节点卸载立即取消本次动画，覆盖 Codex 页面内部用量编辑器替换列表的局部状态变化。外壳通过 data-client-route 与 data-client-route-leaving 表达当前退场语义。方向从进入端身份唯一推导，不再保存方向状态。

动画直接读取全局位移、时长与缓动 token；等待两端 Animation.finished 后结束退场。再次选择时读取动画当前呈现值，取消旧对象并从该画面继续；旧完成回调只能清理自己的记录。隐藏页面、进入二级视图、外部切换和卸载取消动画，不存在超时或 CSS 事件分支。零时长在绘制前完成。缺少任一正文说明当前不在双端列表场景，结束本次视觉记录，不制造虚拟正文或重试。

页头和供应商概览不移动；退场壳绝对定位、inert、aria-hidden，配置面板背景透明。配置组件常驻以保存草稿和展开状态，供应商旧列表只留到动画完成。选择器键盘焦点移交给进入端已选单选项，保留滚动位置；弹层继续使用既有 Portal。

## Alternatives considered

- 共享 CSS 关键帧、各页管理状态：样式复用简单且不增加动画对象管理，但不能消除分裂状态、计时兜底和反向跳变。
- CSS animationend / animationcancel 加精确计时：保留现有事件模式成本较低，但事件仍要识别正文和每代动画，完成来源不唯一；使用实际 Animation.finished 和 cancel。
- 两端列表永久挂载并使用 CSS transition：天然支持反向，但供应商不可见列表含轮询卡，永久挂载会改变原有资源生命周期。
- DOM 快照克隆退场：不必保留真实旧列表，但冻结帧没有实际状态与语义，且要抢在 React 提交前克隆；保留一个真实退场周期更直接。
- 只给进入端淡入或整页一起滑动：代码更少，但前者会空帧，后者让共同页头和供应商概览无意义移动。
- 按客户端 key 重建配置编辑器：挂载即播动画，但丢失展开状态；配置继续常驻，供应商按其现有列表语义卸载。

## Consequences

- 收益：两页只有一个动画生命周期实现，删除方向状态、CSS 动画事件、超时兜底和独立关键帧，不保留双实现兼容入口。旧异步完成受 effect 取消标记与选择记录身份两层约束，不能清除新记录。
- 资源边界：隐藏、外部变更、二级视图和卸载取消动画；减少动态效果直接完成。配置草稿与展开状态保留，供应商不可见列表和轮询卡仍按原生命周期卸载。
- 布局边界：两端正文短暂并存，退场壳保留头部占位，供应商两端相同头部与概览高度是列表纵向对齐的前提；16px 位移留在工作区内边距内。配置退场面板透明以露出进入端，确认弹层不放进正文动画包含块。
- 代价：直接使用当前桌面 WebView 的原生动画 API，正文消费者必须传递唯一控制器的 callback ref，控制器读取全局 token；增加工作区 flex 容器以共同拥有退场定位并接续二级编辑器的高度链路。反向续接只保存两个正文当前呈现值，不复制 DOM、草稿或业务状态。
- 验证范围：笔记结构校验、源码差异、删除路径引用和文件/函数长度；按项目约束不运行编译、类型检查或自动化测试。桌面实际动画、快速点选、焦点和编辑器布局尚未运行验证。

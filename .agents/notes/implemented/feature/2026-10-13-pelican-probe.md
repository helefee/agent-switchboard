# Agent Note: SVG 人工观察与本地结果缓存

Status: implemented

## Problem

降智雷达的视觉回答不能使用整数匹配判分，也不能只展示源码。自定义 SVG 题与已保存的 SVG 历史需要保留可观察的图像、原文和明确格式。

## Decision

- 题库与回答契约由后端 `codex_probe/questions.rs` 拥有。目录返回题干、判分规则和来源，前端不复制题库。现行鹈鹕题统一由 [Linux.do 动画题](2026-10-13-linuxdo-pelican-animation.md)拥有，不再提供经典英文 SVG 题入口。
- 已有 `grading_version` 是回答方式的唯一持久化判别：`1` 保留精确非负整数判分，`svg-visual-v1` 保留原题干并交由人工观察。SVG 的 `expected_answer` 为空表示没有标准答案，成功调用仍记 `undetermined`，不伪造通过或失败。
- 自定义题显式选择回答方式；其中 SVG 格式不接受期望整数。历史回填带回题干、规则、期望答案和次数，不从当前题库重新解析。
- 原始最终回答继续由 `probe_runs.final_answer` 保存，当前页和历史详情复用同一个 SVG 展示组件。刷新、重启和查看历史只读数据库；展示阶段不产生模型调用，不新增浏览器持久化或第二份图像缓存。
- 完整 SVG 从回答文本或 Markdown 代码块提取，经 XML 解析后以图片资源展示，不注入应用文档；解析或图片加载失败保留原始回答并显示具体状态。用量、耗时、配置快照和保存失败重试沿用现有链路。

## Related decisions

检索活跃笔记中的 `probe`、`雷达`、`降智`、`鹈鹕` 和 `pelican`。仅 [会话操作布局](../../implemented/bug-fix/2026-09-24-session-operations-layout.md) 提及雷达历史的共享分页间距，属于不同决定，本次保留其布局契约。现有 proposed 笔记处理供应商诊断和用量可用性，不重叠。

[Linux.do 动画题](2026-10-13-linuxdo-pelican-animation.md)扩展 HTML 回答方式，继续复用这里的人工观察与原文缓存决定；自定义 SVG 与已保存的 SVG 回答保留图片上下文，与 HTML 文档预览分开。

## Alternatives considered

- **把 SVG 渲染成功作为自动通过**：无需人工查看，能直接复用通过率；但能解析不等于鹈鹕和车架画对，机械判分会误导用户，故采用人工观察并保留整数题的判分含义。
- **另存 SVG 文件或浏览器缓存**：能直接复用图片路径；但原始回答已在雷达数据库中持久化，第二份数据会增加删除、刷新和保存失败的一致性负担，故只按原始回答派生展示资源。
- **新增回答类型列并迁移数据库**：类型字段直观且能让期望答案可空；但已有规则版本足以唯一决定回答方式，无需新增同义事实或迁移历史。

## Consequences

- SVG 视觉题不进入整数输出与自动判分路径。图像质量由用户直接观察，UI 的逐次结果、汇总和历史行均显示人工观察，不展示虚构通过率。
- 原始 SVG 回答包含 Markdown 和首尾空白时保持原文保存；图像资源只在展示阶段派生，无独立缓存、迁移或删除路径。重复轮询时依据回答字符串复用解析结果。
- SVG 缺失、XML 无效或图片加载失败时明确提示，仍可展开原始回答。图片使用独立图像上下文，禁用脚本和外部资源，因此依赖外部图片或样式的输出可能显示不完整。
- 原有整数题、用量与配置快照、批次停止和保存失败重试共用原有链路。题库规则版本被明确解析，未知规则报错，不静默落入整数判分。
- 聚焦回归用例覆盖原始题干、显式自定义回答方式、SVG 调用不判分、原文保留、数据库重新打开、历史汇总与删除。用例只更新和新增，遵照项目指令不运行编译、类型检查或自动化测试。
- 笔记结构校验与改动差异审查是本次执行的验证。真实 CLI 调用、WebView 图像显示和重启恢复仍未实测。

# Agent Note: 偏好设置预览卡与受控循环演示

Status: implemented

## Problem

偏好设置的多值选项（主题、界面缩放之外，还有关闭行为、动效、启动页面、日志级别）原先全部是文字分段控件。其中「关闭行为」最易误解（点 X 到底退没退出），「减少动效」「日志级别」的档位差异纯靠文字想象。用户要求设置界面尽量以可视化图形呈现，并以 ChatGPT 外观设置为参照。

## Decision

`src/components/AppPreviewCards.tsx` 是可视化偏好的唯一所有者：`AppPreviewSetting`（隐藏原生 radio 的预览卡组，无障碍契约与共享段控件逐字一致）+ 六族预览组件，全部共享 96×64 画布语法、应用自身窗口解剖与语义色（行动蓝 / 警告橙 / 错误红），色值为字面量而非主题令牌——每张缩略图必须描绘它所代表的对象本身，不随设置页当前主题变色。

- 主题：浅色 / `clipPath` 对半系统 / 深色三张窗口图。
- 界面缩放：窗框与内容面固定，文字及按钮在以内容左上角为锚点的预留空间内同比缩放；图标轨标记同比放大，位置固定。内容按最大 125% 比例预留边距，四档均完整显示，不通过裁剪表达缩放。
- 关闭行为：窗口虚影 + 虚线箭头落入托盘角标（隐入托盘）对比虚线窗框 + 错误红叉 + 单条停机线（退出）。
- 减少动效：同一轨道上的行动蓝光点——「跟随系统」卡往返运动，「减少」卡静止并配停止条。
- 启动页面：图标轨高亮首项（供应商）对比高亮第三项 + 时钟（上次访问）。
- 日志级别：深色控制台内 debug/info/warn/error 四行日志按所选阈值逐级裁剪（静音 = 空控制台）；行色沿用运行日志级别胶囊语义（debug=行动蓝、warn=警告橙、error=错误红、info=中性）。

界面语言与开关类偏好保持文字控件：语言的选项文字本身就是内容，开关语义已清晰，强行图形化是装饰不是信息。

`base/app-settings.css` 唯一拥有卡片布局和状态样式。预览行始终为单列，窄容器规则只改变文字段控件、字体选择器和快捷键的布局，不重置全部设置行。卡片的选中态与禁用态直接由原生 radio 的 `:checked` / `:disabled` 派生，不保留第二份选中 class 或禁用标记；禁用时弱化卡片、显示不可用光标并关闭悬停强调。

偏好设置大组之间同时使用 32px 容器留白和一条全宽细线，细线下方到组标题保留 16px；组内继续只在相邻设置行之间画细线，不给标题或首末项重复加线。`DESIGN.md` 拥有这项视觉约定。

### 受控循环演示

「跟随系统」动效卡是应用唯一的循环演示动画，构成对「不使用循环装饰动画」设计禁例的受控例外——循环本身就是选项含义，不是装饰。冻结规则镜像动效令牌的两条归零条件（`prefers-reduced-motion` 且跟随系统、显式 reduce 偏好），应用处于减少动态效果时两卡一致静止；该静止本身就是 reduce 模式的诚实写照。禁例本体不改，例外仅由此卡持有。

## Alternatives considered

- **全部偏好图形化（含语言、开关、快捷键）**：一致性最强、最「彻底」；但语言的图形无增益（选项文字即内容）、开关画图沦为装饰、快捷键已是交互式录入控件，违反「配置事实优先于装饰」的首要设计优先级。否。
- **动效预览用两帧 GIF/逐帧 SMIL 而非 CSS transform 循环**：实现一次播放看似克制；但选项对比需要持续可感知，一次性动画在用户看卡时已播完，演示失效。CSS transform 循环可被两条 reduce 条件精确冻结。否。
- **日志级别用文字 + 色点（不裁剪行）**：更省绘制；但「按阈值裁剪」才是运行时过滤器的真实行为，全行展示会暗示「日志都会被记录只是着色」。裁剪阶梯是唯一诚实表达。否。
- **保留通用窄屏重置，再提高预览行选择器优先级**：改动最少，但会保留一条无必要的布局重置和一条补偿覆盖；删除重置即可让普通行继承原布局、预览行继承单列布局，因此不增加覆盖分支。
- **扩大缩放预览的裁剪区域**：可以露出放大后的全部形状，但会让内容侵入窗框和画布边缘。固定结构、为最大比例预留内容空间，才能同时表达完整窗口和控件同比缩放。

## Consequences

- 收益：六个多值偏好全部一眼可读；缩略图复用应用自身解剖与语义色，与真实界面互为镜像；无障碍行为（方向键、读屏）与段控件零分叉。
- 代价：新预览必须遵守同一画布语法，并在最大缩放比例下保留内容边距；大组分隔增加 16px 标题前内距；循环演示例外需要在后续动效审查中持续被认领（它是唯一合法的循环）。
- 差异检查、选择器与消费者静态核对通过。`npm run verify-notes` 因 `npx` 获取 `tsx` 时 npm registry 域名解析失败（`ENOTFOUND`）而未完成；使用本机 Node.js 24 直接执行同一组三个校验脚本，笔记树、格式和归档校验均通过。本轮遵守项目规则，不运行编译、类型检查或自动化测试，不以代码检查替代实屏验收。后续实屏检查覆盖六组卡片的选中与禁用反馈、reduce 偏好下两卡静止、日志阶梯逐级裁剪、窄容器单列换行，以及四档缩放的完整内容和大组分隔线。

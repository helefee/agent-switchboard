# Agent Note: 安装器环形百分比进度

Status: implemented

## Problem

安装器的安装进度原是一根 4px 线性条，且引擎对 UI 没有任何进度上报——安装期间只能播一条不确定动画（系统关闭动画时退化为静止的 35% 填充），既没有百分比也没有任何数据展示，长安装阶段用户无从判断进展。

## Decision

引擎与窗口之间建立单向进度契约：`InstallerEngine.Run` 接收 `IProgress<InstallProgress>`，`InstallProgress` 携带全局分数、阶段（`RuntimeDownload / RuntimeInstall / EngineExtract / EngineInstall`）与字节计数。全局分数的权重唯一归引擎所有——运行时缺失时下载 0–40%、装运行时驻留 40%、引擎释放 40–55%、引擎写入 55–99%；运行时已存在（多数机器）时释放 0–30%、写入 30–99%。

可测量的子步骤用真实字节：WebView2 下载用 `DownloadProgressChanged`，引擎释放按分块复制字节数（512KB 节流上报）。引擎写入阶段的最终大小不可知，按 250ms 轮询目标目录递归字节数、以嵌入引擎负载体积为参照做收敛曲线推进，封顶 99%，引擎进程退出后才报告 100%——不用时间伪造进度。

窗口侧把 4px 条整体删除（含 Theme.xaml 的不确定动画样式，无兼容路径），换成 116px 圆环：`Path` 轨道 + 活动蓝圆弧（`PathGeometry` 圆弧，从 12 点顺时针，两端圆头），环心 26px 显示字体百分比；环下两行居中文字：当前阶段（`InstallerText.Phase`）与数据行「版本 · 已下载/已释放/已写入字节数 · 安装位置」，路径超宽省略号截断。`Progress<T>` 把报告 marshal 到 UI 线程，环、百分比、阶段、数据行由同一次报告驱动；全部为确定性渲染，与系统动画开关无关。

## Alternatives considered

- 保留线性条只加百分比文字：改动最小，但线性条对 680×600 的居中构图没有信息优势，且不解决"无数据展示"的诉求，放弃。
- 时间插值让引擎写入阶段匀速爬向 100%：观感最平滑，但百分比是编造的，慢机器上会在 99% 假死或提前到顶，违背"进度是事实"，放弃。
- 以负载体积的固定倍数（如 1.4×）作期望安装量线性映射：写入字节数超过参照后会撞顶回落，需要 clamp 和魔法系数；收敛曲线天然单调有界，参照值直接复用真实存在的负载体积，不引入新常量，放弃。

## Consequences

- 收益：安装期间始终有百分比与阶段/字节事实；WebView2 下载这一最不可控的阶段有真实进度；删除了整段不确定动画样式，Theme.xaml 少一个特例。
- 代价：引擎写入段的百分比是收敛估计，磁盘慢时会在中低区间停留较久（数据行的已写入 MB 始终是真实值，作为补充事实）；引擎阶段每 250ms 全树扫描目录字节，安装目录是扁平应用文件树，开销可忽略，但若未来安装目录引入深层嵌套或联接点需重新评估。
- 契约：`InstallProgress.Fraction` 是全局分数，窗口不得再自行加权；新增安装阶段必须同时给 `InstallerText.Phase` 补文案并归入权重段，否则阶段名显示为"正在写入应用文件"。

# Agent Note: 供应商高级设置完整显示

Status: implemented

## Problem

新建和编辑供应商时，高级设置先隐藏在外层披露区，Responses 能力、Codex 供应商能力和备注又各自折叠。用户无法直接浏览和编辑完整设置，需要逐层展开；空备注和默认能力尤其容易被忽略。

## Decision

`ProviderAdvancedSettings` 统一拥有 Claude、Codex 第三方与官方登录表单的常驻高级设置区域。外层与内部 Responses 能力、供应商能力、备注移除 `details` / `summary`、展开状态与箭头，改为静态分组、标题和原有字段完整显示。协议和能力决定的字段适用条件、参数独立编辑页及现有草稿和保存流程保持同一所有者。

高级设置布局复用全局表单原语、间距、实体内容面与浅层子模块。高级设置专属折叠样式及失去消费者的展开、按需配置、备注摘要文案被删除；`DESIGN.md` 拥有当前交互事实。连接测试与模型区的披露行为属于其他模块，不进入此简化。

## Alternatives considered

- 保留 `details` 并默认展开：改动小且保留原有键盘语义；但仍可收起且需要维护披露状态和动画，不满足移除展开收起功能的要求。
- 只删除最外层折叠：共用容器一次变更即可覆盖全部入口；但 Responses 能力、供应商能力和空备注仍被隐藏，无法实现完整显示。

## Consequences

新建和编辑的 Claude、Codex 第三方及官方登录表单直接呈现适用的高级设置子模块；无需先展开就能填写空备注或配置能力。备注使用真实标签关联输入框，字段仍绑定同一草稿，能力更新和参数页仍通过原有处理函数修改草稿，没有新增配置源。

完整展示增加编辑器的内容高度，由已有中部滚动区域承载，固定头部与保存栏继续由 `EditorFrame` 拥有。这项简化限定于高级设置；若未来重新引入折叠，需要重新评估完整可见的需求，不复用已删除的状态和样式。

## Verification

验证范围为 `git diff --check`、高级设置四个组件的披露状态与箭头残留检索、已删除文案与专属 CSS 选择器的消费者检索，以及项目要求的 `npm run verify-notes`。React 人工复核关注标签语义、状态删除后的导入、字段适用条件与草稿回调。

按照项目约束，本次不运行编译、类型检查或自动化测试。运行界面的实际布局尚未验证，静态检查不作为界面验收。
